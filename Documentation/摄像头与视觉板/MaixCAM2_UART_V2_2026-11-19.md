# MaixCAM2 小球识别 UART V2 数据包格式

本文对应当前 `main.py` 的 `send_v2()`、`crc8()` 和 `BallTracker.output()` 实现。

## 1. 通信与坐标约定

| 项目 | 当前设置 |
| --- | --- |
| 发送串口 | UART4，设备路径 `/dev/ttyS4` |
| 波特率 | 115200 bit/s |
| 协议版本 | V2，版本字段固定为 `0x02` |
| 数据包长度 | 固定 16 字节 |
| 字节顺序 | 所有 16 位字段均为小端序：低字节在前 |
| 发送频率 | 最高约 50 包/秒，实际取决于主循环处理速度 |
| 当前图像宽度 | 640 像素，绝对横坐标范围 0～639 |
| 当前位置零点 | `CENTER_X_PX = 284.0` |
| 当前像素标尺 | `PIXELS_PER_CM = 20.0`，即每厘米 20 像素 |

横坐标从左向右增大。相对位置大于 0 表示球在零点右侧，速度大于 0 表示球向右运动。
零点与像素标尺是当前标定值，后续修改标定时，数据包结构和物理单位保持不变。

## 2. 数据包布局

```text
AA 55 | version | status | sequence | ball_x | position | speed | age_ms | crc8 | 17
 2B       1B       1B        2B         2B       2B        2B      2B       1B    1B
```

| 字节偏移（从 0 开始） | 字段 | 类型 | 字节数 | 含义与单位 |
| --- | --- | --- | --- | --- |
| 0～1 | 包头 | 固定字节 | 2 | `0xAA 0x55` |
| 2 | version | `uint8` | 1 | 固定 `0x02` |
| 3 | status | `uint8` | 1 | 状态位，见下一节 |
| 4～5 | sequence | `uint16` | 2 | 包序号；发送调用未抛异常后加 1，65535 后回到 0 |
| 6～7 | ball_x | `int16` | 2 | 滤波或预测后的绝对横坐标，单位为像素 |
| 8～9 | position | `int16` | 2 | 相对零点的有符号位移，每单位 **0.01 cm** |
| 10～11 | speed | `int16` | 2 | 有符号横向速度，每单位 **0.1 cm/s** |
| 12～13 | age_ms | `uint16` | 2 | 距上次成功采用真实测量的时间，单位为 ms |
| 14 | crc8 | `uint8` | 1 | 对偏移 2～13 共 12 字节计算的 CRC-8/ATM |
| 15 | 包尾 | 固定字节 | 1 | `0x17` |

其中 `int16` 必须按有符号 16 位整数解析，负数采用二进制补码。`ball_x` 虽然类型是 `int16`，当前发送值限制在 0～639。

Python 负载打包格式为：

```python
"<BBHhhhH"
# <：小端；B：uint8；H：uint16；h：int16
```

## 3. 状态字段 status

状态位可以按位或组合，接收端应按位检查，不要仅判断它是否等于某个固定值。

| 位 | 掩码 | 名称 | 含义 |
| --- | --- | --- | --- |
| bit0 | `0x01` | VALID | 本包位置有效，可以交给控制逻辑使用 |
| bit1 | `0x02` | MEASURED | 本轮成功融合了真实 YOLO 检测 |
| bit2 | `0x04` | PREDICTED | 本轮没有实测更新，但仍在短时有效预测期内 |
| bit3 | `0x08` | OUTLIER | 本轮有被拒绝的异常候选，且未采纳实测 |
| bit4～7 | — | 未使用 | 当前程序不置位；旧版 CV 兜底标志 `0x10` 已停用 |

常见组合：

| 状态值 | 含义 |
| --- | --- |
| `0x03` | 有效位置 + 本轮实测更新 |
| `0x05` | 有效位置 + 本轮预测 |
| `0x0D` | 有效位置 + 本轮预测 + 拒绝异常候选 |
| `0x00` | 无有效位置 |
| `0x08` | 无有效位置，同时拒绝了异常候选 |

控制器使用前的关键检查：

```c
if ((status & 0x01u) != 0u) {
    /* 可以使用本包位置；也可以根据 MEASURED/PREDICTED 决定控制策略。 */
} else {
    /* 按控制器自己的失效策略处理，不能把旧位置或速度0当作新的有效测量。 */
}
```

当前 `PREDICT_VALID_S = 0.15`：距离最近真实测量超过 150 ms 后，不再置 VALID。
无效包仍会发送。尚未成功测量时 `age_ms = 65535`；长期丢测时年龄也会饱和到 65535。
无效时的位置可能是最后一次真实测量，速度字段为 0；这些字段不能用于判断球实际停止。

控制器还应检查接收超时：如果根本没有新包到达，旧包上的 VALID 位不会自行变化。

## 4. 数值换算

发送端输入 `x` 为绝对像素横坐标，`v` 为像素速度（px/s）。

```python
ball_x = round(x)
position = round((x - CENTER_X_PX) / PIXELS_PER_CM * 100.0)
speed = round(v / PIXELS_PER_CM * 10.0)
```

发送时 `ball_x` 限制到图像横坐标范围，`position` 和 `speed` 限制到 `int16` 范围 −32768～32767。

接收端恢复物理量：

```c
float position_cm = (float)position / 100.0f;
float speed_cm_s = (float)speed / 10.0f;
```

相对位置和速度字段已完成单位换算，接收端不应再除一次 `PIXELS_PER_CM`。
由于字段分别取整，使用 `ball_x` 重新计算的位置可能与 `position` 存在少量量化差异。

## 5. CRC 校验

| 参数 | 值 |
| --- | --- |
| 算法 | CRC-8/ATM，也称 CRC-8/SMBUS |
| 多项式 poly | `0x07` |
| 初值 init | `0x00` |
| 输入/输出反射 | 均为 False，按高位优先移位 |
| 结果异或 xorout | `0x00` |
| 校验范围 | 偏移 2～13，即从 version 到 age_ms 的 12 个字节 |
| 不参与校验 | 包头、CRC 字节本身、包尾 |
| 标准测试 | ASCII `123456789` 的 CRC 为 `0xF4` |

接收端 C 参考实现：

```c
#include <stdint.h>
#include <stddef.h>

static uint8_t crc8_atm(const uint8_t *data, size_t size)
{
    uint8_t crc = 0x00u;
    for (size_t i = 0; i < size; ++i) {
        crc ^= data[i];
        for (unsigned bit = 0; bit < 8; ++bit) {
            crc = (uint8_t)((crc & 0x80u)
                ? ((crc << 1) ^ 0x07u)
                : (crc << 1));
        }
    }
    return crc;
}

/* frame 已经收齐16字节，下面三个条件仍需检查包头和版本。 */
/* frame[14] == crc8_atm(&frame[2], 12) */
```

## 6. 完整十六进制示例

输入状态如下：版本 2、有效实测 `status=0x03`、序号 1、球心 `x=304 px`、速度 `v=200 px/s`、测量年龄 10 ms。
按当前零点 284 和标尺 20 px/cm，得到：

- 绝对横坐标：304，即 `0x0130`，小端字节为 `30 01`。
- 相对位置：+1.00 cm，字段值 100，即 `64 00`。
- 速度：+10.0 cm/s，字段值 100，即 `64 00`。
- 测量年龄：10 ms，即 `0A 00`。

完整数据包为：

```text
AA 55 02 03 01 00 30 01 64 00 64 00 0A 00 13 17
```

校验输入为 `02 03 01 00 30 01 64 00 64 00 0A 00`，CRC 为 `0x13`。

## 7. 接收端解析建议

1. UART 是字节流，一次接收不一定恰好是一包；用接收缓存累计数据。
2. 搜索 `AA 55`，从该位置开始等待收齐 16 字节。
3. 检查版本为 `02`、包尾为 `17`，然后检查 CRC。
4. 校验失败时向后移动一个字节重新搜索包头；不要把负载中的 `AA 55` 或 `17` 当作可靠分隔符。
5. 校验通过后按固定偏移、小端顺序解析，先检查 VALID，再使用物理量。
6. 用序号观察丢包与重复包，注意 16 位回绕；同时维护独立的接收超时计时。

若使用 C 结构体映射接收缓存，必须处理结构体填充、字节序和未对齐访问；按字节显式解码更容易跨平台保持一致。
