# 灰度循线一圈

适用 C/LL 固件的 LAP 页。按车辆前进方向看，主控归一化灰度左到右为 CH1～CH8，黑色为低电平。实际八路线束在 C5 输入端反序，当前程序已用 `GRAY_REVERSE_CHANNELS=1` 修正；启动前以主控屏幕核对实际左右。
目标赛道为 A 题的闭合黑线，A 点有横向起停标记，按顺时针放车。圈内其他位置不能有相同的横线停车标记。

## 首次确认方向

1. 车轮架空，将窄黑条放在灰度 CH4/5 下，LAP 页应显示 `POS +0`；整排全白时程序拒绝起步并显示 `ALIGN LINE`。
2. 在停止时用 SPD 选 800 CPS，MAP 为 A，按 RUN，观察两轮是否都朝着让车前进的方向转动。任意键停止。
3. 如果两轮一起朝后，停车后按 MAP 切到 B 再检查。当前默认 MAP A 为实车左轮 J6 正、右轮 J4 负，B 同时反转；该选择不改变灰度左右顺序。
4. 如果仍有一轮方向不符，或出现 `ENC ERROR`，先保留现象排查电机/编码器方向，不落地继续跑。

2026-11-17 用户架空目视确认旧组合（J4 正/J6 负）两轮均后退，已将其反向组合固化为 MAP A，并将两路前进编码器归一化为正。
随后用户确认实车 J6 是左轮、J4 是右轮，现已在板层统一修正左右角色，避免灰度差速反向；详见[映射修正记录](../validation/2026-11-17-lap-side-map.md)。
仅交换电机还不够：用户进一步确认旧主控显示的最左探头是 8，灰度也需反序。当前两端映射及端到端转向测试见[灰度反序修正](../validation/2026-11-17-lap-gray-map.md)。
MAP 不写入 Flash，上电回到默认 A。现有 ALL 同向电气输出仅用于联调，不作为车辆前进方向依据。

## 运行一圈

1. 在当前比赛赛道上，将灰度探头放在 **A 横线**，车头朝 B，使用实车确认过的 **MAP A**。识别到起点标记后，程序会在两处半圆弯之前收速，并按照实测差速逐步开始右转。只压纵向窄线或选择 MAP B 时，仍可启动普通灰度循线。
2. 按 RUN。放在 A 横线或其分段边缘时先显示 `LEAVE A`，以不超过 800 CPS 的共同目标直行驶离，随后显示 `FOLLOW`。普通窄线起步直接循线。负偏差（线在左）降低左轮目标、提高右轮目标；正偏差反之。
3. 离开起点进入普通窄线后，程序开始准备停车检测。底部 `A ARMED` 表示离开起点、运行时间和编码器行程条件均满足。
4. 返回时检测覆盖至少四路、至多两段的标记，保持至少 10 ms 后停车并显示 `DONE`。任意键或 BLE `!` 可提前停止。

接近 A 的 39000 计数后显示 `A NEAR`，共同目标限至 1100 CPS；在 41000～47000 计数内还允许持续 30 ms 的三路部分覆盖标记停车。该窗口取自当前赛道实测，原四路识别继续有效。若保护停车发生在其他位置，下一次 RUN 前先将车放回 A。

默认直道 **4600 CPS**，从 A 横线顺时针起步的两段弯道最高 **3100 CPS**。停车时按 SPD 循环选择 800、1800、2200、3300、4600 CPS。选 3300 即回到实车跑稳的 3300/2200 档。高档提前收速，再逐步转入弯道。黑线偏离 CH4/CH5 或外轮 PWM 余量不足时，控制器降低共同速度，优先纠偏。更换路线或轮胎后应重新核对弯道里程。[高速档验证](../validation/2026-11-18-lap-fast.md)、[原版固件备份](../../Firmware/releases/lap-3300-BF33A9F7/README.md)
CPS 是编码器计数/秒，尚未换算成 m/s。90 s 是异常运行截止时间，不是赛题的 30 s 成绩目标。
2200 CPS 旧版实测圈时为 24.333 s、24.262 s，用户确认两次回 A 停车。比较新版时，从同一 A 点起步，记录圈时和实际停车位置。遥测中单段窄线的 `abs(gray_position) <= 500` 表示线中心落在 CH4 到 CH5 的范围内。A 横线和驶离阶段应单独统计。[旧版两圈记录](../validation/2026-11-17-lap-repeat.md)

## 停止提示

| 提示 | 含义与后续检查 |
| --- | --- |
| READY | 等待 RUN；保持停止 |
| ALIGN LINE | 起步时没有普通单段黑线或横线；检查探头下方目标 |
| FOLLOW | 正在循线 |
| LEAVE A | 正从起点标记驶离；普通窄线稳定 100 ms 后切换 FOLLOW，最多 1.5 s 或 1000 计数 |
| DONE | 停车条件已满足；确认实物是否回到 A |
| STOPPED | 按键或 BLE 停止，不自动恢复 |
| LOST LINE | 无黑线持续 150 ms；检查转向、黑白校准、传感器高度或离线原因 |
| BAD LINE | 多段/异常线持续 250 ms，或起点横线一直未离开；检查路线和标记 |
| ENC ERROR | 编码器不动、反馈反向或计数突变；检查方向、供电、J10 与反馈 |
| DRIVE ERR | 轮驱动唤醒/使能/nFAULT 保护停止 |
| LOOP LATE | 10 ms 控制调度间隔超过 50 ms；保留遥测排查 |
| TIMEOUT | 90 s 内未完成停车；检查标记宽度和是否回到起点 |
| NO A MARK | 平均行程已到 60000 计数却未识别 A；检查标记采样和实际圈长，当前为保护停车而非回到 A |

停车识别只在已离开起点、运行至少 2 s、平均行程至少 30000 计数后启用。当前约 6.142 m 赛道的一圈候选记录约 43000 计数；30000～60000 是暂定识别窗口，不是轮径或圈长标定。更换场地或轮胎后须重测，不能直接沿用。
四路门限允许横线边缘部分覆盖；多段边缘起步采用受限驶离阶段，常规循线中的异常输入仍执行保护。
当前停车会撤销轮驱动使能；停车距离、车体基准点与探头到车体的偏移仍需实物标定。

## 蓝牙记录与更新

```powershell
./Firmware/flash-wireless.ps1
.scratch/firmware-tools/Scripts/python.exe Firmware/tools/monitor.py --ble F8:2E:0C:F3:68:37 --lap --seconds 90 --out lap.csv
```

`--lap` 只停止并选择 LAP 页，仍由实物 RUN 启动。测试期间不要再次用带 `--lap` 的命令连接，否则会停止当前任务。
只观察运行时，去掉 `--lap`；串口错误、停止原因、双轮目标/反馈及 A 标记状态见[遥测参考](../reference/firmware-telemetry.md)。
v6 在 LAP 运行时约每 100 ms 发送，停止和其他页仍为 500 ms。除 v5 控制诊断外，还记录驶离阶段、允许停车后的标记次数和最大覆盖通道数；用 MCU 时间比较转向与反馈，不用 BLE 到达间隔代替控制周期。

Debug 的 `C5:CHECK` 是架空方向检查专用命令：固定 15% 输出约 1.5 s，然后自动停止，不要求探头在黑线上；Release 不提供该入口。赛道上使用 RUN 和正常灰度保护。
实现依据、同学代码取舍及本轮实测范围见[首圈验证记录](../validation/2026-11-17-lap.md)。
