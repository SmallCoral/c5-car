# 灰度循线一圈

适用 C/LL 比赛菜单的第二题及设备调试的 LAP 页。按车辆前进方向看，主控归一化灰度左到右为 CH1～CH8，黑色为低电平。实际八路线束在 C5 输入端反序，当前程序已用 `GRAY_REVERSE_CHANNELS=1` 修正。
目标赛道为 A 题的闭合黑线，从 A 点顺时针放车。比赛第二题以按键位置为里程起点，场地只需提供途中循线用的纵向黑线。

## 从比赛菜单启动第二题

第二题的独立实车基线为 `D97DBD0E`，当前三题合并版 `EC2ED1B4` 沿用相同的停车门槛。上场前可用蓝牙查询主控身份。[固件查询与恢复](../../Firmware/releases/README.md)

1. 从上电首页按 SW3 选「第二题 循线停车」，短按 SW2 进入准备页。这里可以从左至右查看八路黑线探头。上电默认为 4600 CPS，SW3（SPD）可选原有的五档速度。
2. 将车放在实物 A 点，车头朝顺时针方向，短按 SW2 立即起跑。每次按键都以当时的左右轮编码器为起点。探头已压到纵向窄线时直接循线，起步时全白则显示 `FIND LINE`，低速直行寻找窄线，最多 1.5 秒或 1000 计数。
3. 运行页显示 `FOLLOW`、双轮实测速度、当前里程 / 41800 和用时。平均里程达到 41800 计数即关闭双轮并显示「一圈停车」。末弯按灰度正常纠偏，最后 900 计数才平滑收速。中途按 SW5 可停车并返回准备页。
4. 比赛入口限时 30 秒。按相同车身基准点摆车和量停车位置，用尺核对回到 A 后的 3 cm 误差。41800 取自实车四次回 A 的触发里程，终点之后的实际滑行也计入尺量。[第二题停车实测](../validation/README.md)

## 设备调试页确认方向

1. 车轮架空，将窄黑条放在灰度 CH4/5 下，LAP 页应显示 `POS +0`；整排全白时程序拒绝起步并显示 `ALIGN LINE`。
2. 在停止时用 SPD 选 800 CPS，MAP 为 A，按 RUN，观察两轮是否都朝着让车前进的方向转动。任意键停止。
3. 如果两轮一起朝后，停车后按 MAP 切到 B 再检查。当前默认 MAP A 为实车左轮 J6 正、右轮 J4 负，B 同时反转；该选择不改变灰度左右顺序。
4. 如果仍有一轮方向不符，或出现 `ENC ERROR`，先保留现象排查电机/编码器方向，不落地继续跑。

2026-11-17 用户架空目视确认旧组合（J4 正/J6 负）两轮均后退，已将其反向组合固化为 MAP A，并将两路前进编码器归一化为正。
随后用户确认实车 J6 是左轮、J4 是右轮，现已在板层统一修正左右角色，避免灰度差速反向；详见[映射修正记录](https://github.com/SmallCoral/c5-car/blob/e631797d99cd60486eccc874f66cc99cdf3f7496/Documentation/validation/2026-11-17-lap-side-map.md)。
仅交换电机还不够：用户进一步确认旧主控显示的最左探头是 8，灰度也需反序。当前两端映射及端到端转向测试见[灰度反序修正](https://github.com/SmallCoral/c5-car/blob/e631797d99cd60486eccc874f66cc99cdf3f7496/Documentation/validation/2026-11-17-lap-gray-map.md)。
MAP 不写入 Flash，上电回到默认 A。现有 ALL 同向电气输出仅用于联调，不作为车辆前进方向依据。

## 设备调试 LAP 页按横线停车

1. 在当前比赛赛道上，将灰度探头放在 **A 横线**，车头朝 B，使用实车确认过的 **MAP A**。识别到起点标记后，程序会在两处半圆弯之前收速，并按照实测差速逐步开始右转。只压纵向窄线或选择 MAP B 时，仍可启动普通灰度循线。
2. 按 RUN。放在 A 横线或其分段边缘时先显示 `LEAVE A`，以不超过 800 CPS 的共同目标直行驶离，随后显示 `FOLLOW`。普通窄线起步直接循线。负偏差（线在左）降低左轮目标、提高右轮目标；正偏差反之。
3. 离开起点进入普通窄线后，程序开始准备停车检测。底部 `A ARMED` 表示离开起点、运行时间和编码器行程条件均满足。
4. 返回时检测覆盖至少四路、至多两段的标记，保持至少 10 ms 后停车并显示 `DONE`。任意键或 BLE `!` 可提前停止。

接近 A 的 39000 计数后显示 `A NEAR`，共同目标限至 1100 CPS；在 41000～47000 计数内还允许持续 30 ms 的三路部分覆盖标记停车。该窗口取自当前赛道实测，原四路识别继续有效。若保护停车发生在其他位置，下一次 RUN 前先将车放回 A。

默认直道 **4600 CPS**，从 A 横线顺时针起步的两段弯道最高 **3100 CPS**。停车时按 SPD 循环选择 800、1800、2200、3300、4600 CPS。选 3300 即回到实车跑稳的 3300/2200 档。高档提前收速，再逐步转入弯道。黑线偏离 CH4/CH5 或外轮 PWM 余量不足时，控制器降低共同速度，优先纠偏。更换路线或轮胎后应重新核对弯道里程。[高速档验证](https://github.com/SmallCoral/c5-car/blob/e631797d99cd60486eccc874f66cc99cdf3f7496/Documentation/validation/2026-11-18-lap-fast.md)、[原版固件备份](https://github.com/SmallCoral/c5-car/blob/e631797d99cd60486eccc874f66cc99cdf3f7496/Firmware/releases/lap-3300-BF33A9F7/README.md)
CPS 是编码器计数/秒。设备调试的 LAP 页保留 90 s 保护，比赛第二题使用 30 s 限时。
2200 CPS 旧版实测圈时为 24.333 s、24.262 s，用户确认两次回 A 停车。比较新版时，从同一 A 点起步，记录圈时和实际停车位置。遥测中单段窄线的 `abs(gray_position) <= 500` 表示线中心落在 CH4 到 CH5 的范围内。A 横线和驶离阶段应单独统计。[旧版两圈记录](https://github.com/SmallCoral/c5-car/blob/e631797d99cd60486eccc874f66cc99cdf3f7496/Documentation/validation/2026-11-17-lap-repeat.md)

## 设备调试 LAP 页状态

| 提示 | 含义与后续检查 |
| --- | --- |
| READY | 等待 RUN；保持停止 |
| ALIGN LINE | 起步时没有普通单段黑线或横线；检查探头下方目标 |
| FOLLOW | 正在循线 |
| LEAVE A | 正从起点标记驶离；普通窄线稳定 100 ms 后切换 FOLLOW，最多 1.5 s 或 1000 计数 |
| DONE | 停车条件已满足；确认实物是否回到 A |
| STOPPED | 按键或 BLE 停止，不自动恢复 |
| LOST LINE | 无黑线持续 150 ms；检查转向、黑白校准、传感器高度或离线原因 |
| BAD LINE | 多段/异常线持续 250 ms，或起点横线一直未离开；检查路线和标记 |
| ENC ERROR | 编码器不动、反馈反向或计数突变；检查方向、供电、J10 与反馈 |
| DRIVE ERR | 轮驱动唤醒/使能/nFAULT 保护停止 |
| LOOP LATE | 10 ms 控制调度间隔超过 50 ms；保留遥测排查 |
| TIMEOUT | 90 s 内未完成停车；检查标记宽度和是否回到起点 |
| NO A MARK | 平均行程已到 60000 计数却未识别 A；检查标记采样和实际圈长，当前为保护停车而非回到 A |

调试页在已离开起点、运行至少 2 s、平均行程至少 30000 计数后启用横线检测。30000～60000 计数是该页的识别窗口。更换场地或轮胎后应重新量测一圈行程。
四路门限允许横线边缘部分覆盖；多段边缘起步采用受限驶离阶段，常规循线中的异常输入仍执行保护。
当前停车会撤销轮驱动使能；停车距离、车体基准点与探头到车体的偏移仍需实物标定。

## 蓝牙记录与更新

```powershell
./Firmware/flash-wireless.ps1
.scratch/firmware-tools/Scripts/python.exe Firmware/tools/monitor.py --ble F8:2E:0C:F3:68:37 --seconds 90 --out lap.csv
```

以上采集命令可以在比赛页使用。仅在需要切换到设备调试的 LAP 页时添加 `--lap`，该参数会先停车。
只观察运行时，去掉 `--lap`；串口错误、停止原因、双轮目标/反馈及 A 标记状态见[遥测参考](../reference/firmware-telemetry.md)。
v6 在 LAP 运行时约每 100 ms 发送，停止和其他页仍为 500 ms。除 v5 控制诊断外，还记录驶离阶段、允许停车后的标记次数和最大覆盖通道数；用 MCU 时间比较转向与反馈，不用 BLE 到达间隔代替控制周期。

Debug 的 `C5:CHECK` 是架空方向检查专用命令：固定 15% 输出约 1.5 s，然后自动停止，不要求探头在黑线上；Release 不提供该入口。赛道上使用 RUN 和正常灰度保护。
实现依据、同学代码取舍及本轮实测范围见[首圈验证记录](https://github.com/SmallCoral/c5-car/blob/e631797d99cd60486eccc874f66cc99cdf3f7496/Documentation/validation/2026-11-17-lap.md)。
