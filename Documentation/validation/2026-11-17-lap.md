# 2026-11-17 灰度循线一圈联调

基线为 Git `5c09ee0d09d186b52a6b1959b378c783622240dd` 加前一轮灰度工作区；修改前代码及 OTA 保存在本机 `.scratch/lap-baseline-20261117/`。
用户明确确认：灰度校准后黑白可正常识别，按车辆前进方向看，黑线从左移到右时依次触发 CH1～CH8。此事实已写入根 `AGENTS.md`、灰度说明和交接。
用户确认 A 点有横线，首次检查时车轮架空；后续明确授权无需黑线、直接短时转轮观察。
最终源码与镜像 SHA-256 见[source-manifest.json](../../Firmware/validation/2026-11-17/lap/source-manifest.json)。

## 实现与参考

LAP 是新的默认停止页。灰度 PD 产生左右差速目标，编码器 PI 调节轮 PWM；使用约 10 ms 控制周期、加速斜坡、弯道降速、抗积分饱和和不反转的输出边界。
速度使用编码器计数/秒，800/1300/1800 三档，首轮默认 800，LAP PWM 上限 35%。轮径与每转计数未标定，未声明物理车速。
停车使用 A 横线：稳定离开窄线区至少 100 ms、运行至少 2 s、平均正向编码器行程至少 2000 计数后，至少六路连续命中 20 ms 才结束。未使用同学车的固定圈长数字。
丢线 150 ms、多段/异常线 250 ms、起点横线一直未离开、反馈反向/不动、控制周期超过 50 ms、轮驱动保护或运行 90 s 会停止。故障恢复不会自动重新启动。

| 同学资料 | 采用的思路 | 本项目的调整 |
| --- | --- | --- |
| 26H `XunJi/Xunji.c` | 10 ms 循迹、PD 差速、分阶段加减速、停车线与起步隔离 | 使用已确认的左负右正通道坐标；以毫秒和编码器行程判定起步，横线连续去抖；每次启动复位状态 |
| 21E `Xunji.c` | 多通道权值与目标数量 | 复用现有八路滤波和连续段检测，不把多段或全白直接平均成居中 |
| 22C `pid.c`、`Motor.c`、`encoder.c` | 差速与限幅、编码器速度/行程组织 | 使用 C5 硬件 x4 计数、不清零计数器，独立双轮 PI；没有照搬旧轮径、每转计数或增益 |

精确归档成员及提取摘要见[reference-sources.json](../../Firmware/validation/2026-11-17/lap/reference-sources.json)，原 ZIP 和厂家源码均保留不变。
本轮重写当前平台控制模块，没有将旧 HAL/MSPM0 GPIO 或轮速数值直接套入 C5。

## 初次更新与真实失败

执行 `./Firmware/flash-wireless.ps1`。[首次上传](../../Firmware/validation/2026-11-17/lap/wireless-flash.txt)从灰度版 20,324 B、CRC `B63CDAED` 更新到 23,604 B、CRC `CBD366C1`，111.5 s、18 次重试，上传后运行身份校验成功。

随后运行：

```powershell
.scratch/firmware-tools/Scripts/python.exe -u Firmware/tools/monitor.py --ble F8:2E:0C:F3:68:37 --lap --seconds 90 --out Firmware/validation/2026-11-17/lap/direction-check.csv
```

[181 帧记录](../../Firmware/validation/2026-11-17/lap/direction-check.csv)中出现过实际启动，随后 `lap_status=10`（LOOP LATE），输出清零、使能撤销；[摘要](../../Firmware/validation/2026-11-17/lap/direction-check-summary.json)保留失败。
不能将这次短时编码器变化当作成功循线或一圈完成。

代码复查发现，原显示只对 SPI 发送分条，`ui_render()` 仍同步整屏绘制。已改为同一帧状态快照，每次只绘制并发送 8 行；50 ms 控制迟到保护保留。
新增 `C5:PERF` 查询主循环、显示服务和遥测服务的最大毫秒耗时，用板上记录核实优化效果。

## 架空方向检查

Debug 新增 `C5:CHECK`：仅在停止状态接受，固定 15% PWM、1.5 s 后自动停止，不依赖灰度；仍检查编码器方向/不动、主循环迟到、使能与 nFAULT，板层另保留 3 s 期限。
这是用户本轮明确授权的架空检查入口；普通 LAP 仍由实物 RUN 启动，Release 不包含该命令。
显示修正版 24,204 B、CRC `27A7E536` 已[真实上传](../../Firmware/validation/2026-11-17/lap/wireless-flash-sliced-ui.txt)，98.0 s、13 次重试，身份校验成功。
第一次发起 CHECK 后 BLE 断开，未收到有效运行阶段；[原始失败](../../Firmware/validation/2026-11-17/lap/bench-wheels.txt)保留，[重连记录](../../Firmware/validation/2026-11-17/lap/bench-reconnect.csv)确认使能为 0、轮速为 0。未把它计为检查成功。

确认命令链路和运行镜像后，完成两次架空检查：

| 检查 | 左/右编码器变化 | 固件检查时长 | 结果 |
| --- | --- | --- | --- |
| [首次有效检查](../../Firmware/validation/2026-11-17/lap/bench-wheels-retry-summary.json) | −1695 / −1802 | 1508 ms | 收到 3 帧 DIR CHECK，随后 STOPPED、使能 0 |
| [用户要求重复](../../Firmware/validation/2026-11-17/lap/bench-wheels-repeat-summary.json) | −1655 / −1847 | 1514 ms | 同上，未再发生 LOOP LATE |

`C5:PERF` 实测最大主循环间隔 21 ms、显示服务 19 ms、遥测服务 3 ms；这些是此次观测窗口的最大值，不是所有负载的时序上限。
用户目视确认该旧组合（左正/右负）两轮都后退。已将默认前进改为左负/右正，两路前进编码器原始计数均应为正，保留 MAP 同时翻转能力。
[最终上传](../../Firmware/validation/2026-11-17/lap/wireless-flash-forward.txt)确认运行 CRC `26023F22`，94.1 s、12 次重试；普通上电和升级后仍保持停止。
