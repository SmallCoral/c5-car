# 3300 CPS 巡航与弯道居中

11 月 18 日将 C/LL 的默认直线目标从 2200 提到 3300 编码器计数/秒。转弯以物理 CH4 和 CH5 中间为零点。当天第一版为 `BB32054B`。实车在第一弯冲出后，修正版 `BF33A9F7` 加入从 A 出发的提前减速和按赛道半径给出的基础差速。[控制代码](../../Firmware/src/lap.c)、[配置](../../Firmware/include/config.h)

## 上一版为什么会靠外循线

从 11 月 17 日两次回 A 的记录中选取运行中、已驶离起点、平均行程在 `[2000, 39000)` 的单段窄线帧。371 帧中，167 帧的 `abs(gray_position) <= 500`，即线中心落在 CH4 到 CH5 之间。另有 190 帧偏差达到 +1500 至 +3000，向右偏了 1.5～3 个探头间距。这些帧的轮输出均低于当时的 400‰ 上限。该记录覆盖两次完成的圈，用户另行报告过弯出线。[原始遥测](../../Firmware/validation/2026-11-17/lap-repeat/track-repeat-1.csv)

旧版依靠当下的位置偏差提供持续差速。线回中并稳定后，位置项和微分项都趋于零，编码器阻尼还会抵消正在发生的转向。新版在窄线上依据持续偏差积累转弯所需的轮速差比例，编码器确认轮子正在执行这个方向的修正后才允许继续积累。即使线已回到中心，长弯仍有差速。直线上的小修正会衰减，反向偏差可以撤回旧修正，停车清零。

## 速度与停车

- 停车时 SPD 循环选 800、1800、2200、3300 CPS，上电选择 3300。单轮目标上限为 3500 CPS。LAP 可用 45% PWM，板层原有上限也是 45%。
- 中心附近限制微分引起的轮速跳变。偏出中间两路后增加位置修正，根据位置变化率前看 60 ms 收速。共同速度同时受请求差速、实际差速和两轮剩余 PWM 余量约束，外轮到顶时让内轮降速。
- 从 A 横线驶离的共同目标最高 800 CPS，39000 计数起的终点接近目标最高 1100 CPS。丢线 150 ms、异常线 250 ms 的停车时限继续生效。[操作及停车条件](../how-to/line-following-lap.md)

## 主机与 ARM 验证

源码基线为 `84abdadee05df6177606b2f3b0e4f54efa13ad0b` 加工作区改动，两次镜像分别记录[第一版散列](../../Firmware/validation/2026-11-18/lap-centering/first-image-manifest.json)和[修正版散列](../../Firmware/validation/2026-11-18/lap-centering/source-manifest.json)。工具为 CMake 4.3.1、Ninja 1.13.2、主机 GCC 15.2.0、ARM GCC 14.3.1、Python 3.12.14。主机测试进程的 PATH 包含 CLion 的 MinGW bin。

```powershell
cmake --build Firmware/build/host
ctest --test-dir Firmware/build/host --output-on-failure
Firmware/build/host/test_lap_dynamics.exe
.scratch/firmware-tools/Scripts/python.exe -m unittest discover -s Firmware/tests -p 'test_*.py'
cmake --build Firmware/build/debug
cmake --build Firmware/build/release
./Firmware/flash-wireless.ps1
```

第一版 C 测试 6/6、Python 测试 16/16 通过，ARM Debug 与 Release 生成的应用分别为 25,640 B / `BB32054B` 和 22,196 B / `B2418E03`。测试包含满速时向两侧纠偏、3300 进入 A 减速区、持续弯的差速保持、短暂丢线或横线时冻结学习，以及停车复位。用固定的低速编码器输入测试时，动态限速会让共同目标低于加速斜坡或 A 接近上限。另用足够轮速的输入验证了两个目标值都可达到。[CTest 结果](../../Firmware/validation/2026-11-18/lap-centering/ctest.txt)

模型通过实际的灰度滤波和固件控制器计算 PWM，轮速由独立的电机模型产生。每个版本使用自己的默认档，在相同的 144 组输入上比较。组合涵盖 80/120/160 mm 前视距离、50/100/150 ms 电机响应、固定/抖动控制间隔、两组不等的电机增益，以及直线、左右半径 500 mm 的弯和连续换向。每个模型运行 12 s，以每 2 ms 的采样计算中心占比；长弯统计末 4 s，连续换向从 4 s 的第一次入弯起统计至结束。模型参数未经过实车标定。[旧版逐项结果](../../Firmware/validation/2026-11-18/lap-centering/model-before.txt)、[新版逐项结果](../../Firmware/validation/2026-11-18/lap-centering/model-after.txt)

## 无线与实车

初次只读查询连续三次未搜到 HC-08。用户上电后重连读到旧版 `29D123B8`。上传首次连接中断，工具自动重连，成功连接后的传输耗时 83.8 s，重试 8 次；校验、安装成功。独立重连返回 `C5APP,1,BB32054B,25640` 和 `C5PERF,1,6,5,3`。启动时 LAP 为 READY、双轮目标及 PWM 为零。[升级前查询](../../Firmware/validation/2026-11-18/lap-centering/board-before.txt)、[上传日志](../../Firmware/validation/2026-11-18/lap-centering/wireless-flash.txt)、[升级后查询](../../Firmware/validation/2026-11-18/lap-centering/board-after.txt)

第一圈从 A 起步。2500～9500 计数的直道内，21 个窄线样本全部落在 CH4/CH5 范围，双轮实际均速为 3298 CPS。第一弯在 4.693 s 时左右目标到 2800/200 CPS，4.993 s 时线已越过中心，仍请求向右的半差速 515 CPS。随后左右反摆，6.123 s、14384 计数时触发 LOST LINE，双轮 PWM、目标及使能归零。用户现场反馈“又偏移了”。[首圈遥测](../../Firmware/validation/2026-11-18/lap-centering/track-1.csv)、[停车摘要](../../Firmware/validation/2026-11-18/lap-centering/track-1-summary.json)

## 按实车过弯数据修正

11 月 17 日两圈在约 11500 和 33000 计数附近进入右弯，持续弯内的半轮速差通常为共同速度的 16%～27%。第一版实车却请求过 87%。修正版在 MAP A 从已识别的 A 标记起步时，按这两圈的里程预留制动距离。第一弯从 9800 计数起将共同目标限至 2200 CPS，10500 起在 1000 计数内逐渐加入 20% 的右转半差速。驶出第一弯时逐渐撤回，22300 计数结束该段。第二弯相应窗口后移 21500 计数。灰度继续逐周期纠偏，学习量限于额外的 ±7%，最终半差速最多为共同目标的 38%。从普通窄线或 MAP B 起步时只用传感器循线。里程窗口对应当前车辆和从 A 顺时针出发的赛道。

修正版 ARM Debug 为 25,892 B / `BF33A9F7`，Release 为 22,412 B / `94CF3A1E`。主机 CTest 6/6 通过。新增回归覆盖两处弯前收速、回到直线恢复巡航、经过中心后的反向纠偏和未识别 A 时的行为。原有 144 组通用循线工况通过，另以厂家标称的 12 mm 探头间距和独立的赛道几何模拟从 A 启动，36 组均返回横线停车。正常路段模型居中占比最低 94.3%，平均 98.3%。[最终 CTest](../../Firmware/validation/2026-11-18/lap-centering/ctest-final.txt)、[180 组模型](../../Firmware/validation/2026-11-18/lap-centering/model-final.txt)、[灰度板尺寸依据](../感为八路灰度资料/README.md)
